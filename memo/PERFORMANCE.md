# 性能と動作が重いときの TIPS

## この MOD の処理負荷

| 処理 | タイミング | 負荷 |
|---|---|---|
| 規模の計測（`SpawnScanner.scan`） | `/mopup setup` の瞬間のみ | 重い。ボーダー内を全ブロック走査するので一瞬止まることがある |
| ターゲットモブ集計（`GameManager.findTargets`） | ゲーム中、毎ティック | 軽い。100×100 の範囲のエンティティ検索 1 回 |
| ボスバー更新（`HudManager.update`） | ゲーム中、毎ティック | 軽い。値が変わったときだけパケット送信 |
| 発光の付与 | 発光中、1 秒毎 | 軽い |

- ゲーム中以外（setup 前、クリア後、ゲームオーバー後）は、ティック処理が冒頭で return するので何もしない
- 実測: 敵 34 体・発光中でも Integrated server のティック処理は 10ms 前後（上限 50ms）

ゲームの性質上、次の負荷は増えうる（MOD の処理そのものではない）。

- 時間を真夜中で止めるので、湧き上限まで敵モブが湧き続ける
- 発光中はクライアントで輪郭描画が追加される

## 重いときの原因の切り分け

F3 画面で次を見る。F3+2 で FPS とティック処理時間のグラフも出せる。

| 重い瞬間の状態 | 原因 |
|---|---|
| `Integrated server @ xx/50.0 ms` が 50ms 近くに跳ねる | サーバー側（チャンク生成、モブの処理など） |
| サーバー側は低いまま画面だけカクつく | クライアント側（GC、描画） |
| `Mem: xx%` が 90% 以上から急に下がり、それとカクつきが重なる | GC。割り当てメモリ不足 |
| 右上の `Display:` が内蔵 GPU（Intel など） | 内蔵 GPU で動いている |

サーバー側をさらに調べるなら `/debug start` → `/debug stop` か、[spark](https://modrinth.com/mod/spark) の `/spark profiler`。

## TIPS

### 割り当てメモリを増やす

公式ランチャーのデフォルトは 2GB（`-Xmx2G`）。F3 の `Mem: xx% yyy/2048MB` で確認できる。

プレイ中は `Allocation rate` が 100MB/s 程度になり、2GB だと GC が頻繁に走ってカクつきやすい。ランチャーの「起動構成 → 編集 → その他のオプション → JVM引数」で `-Xmx4G` 程度にする。

増やしすぎ（8GB など）は逆効果。PC の物理メモリが足りなくなり、Windows がディスクに退避（ページング）して余計に重くなる。

### PC のメモリを空ける

マイクラはヒープの他にネイティブ・描画用で 1〜2GB 使う。起動前の使用率が高いと満杯になりやすいので、ブラウザや IDE などを閉じてから遊ぶ。

開発環境の `./gradlew runClient` で遊ぶと、Gradle のプロセスも同時に動いて重い。普通に遊ぶならビルドした jar をランチャーの mods フォルダに入れる。

### 専用 GPU で動かす

GPU が 2 つあるノート PC では、内蔵 GPU で動いてしまうことがある。Windows の「設定 → システム → ディスプレイ → グラフィック」で javaw.exe を「高パフォーマンス」にする。

### チャンク生成の負荷を減らす

setup 前にワールドを物色するとチャンク生成が走り重くなりやすい。

- 描画距離・シミュレーション距離を下げる
- 速く飛び回らない
- [Chunky](https://modrinth.com/plugin/chunky) で事前に生成しておく

### 軽量化 MOD

いずれも Fabric 対応。

- Sodium: 描画を高速化
- Lithium: サーバー処理を軽量化
- FerriteCore: メモリ使用量を削減
- C2ME: チャンク生成を並列化
